# Working agreement

## Scope

This repository contains small Hazelcast examples and larger examples that combine them. Each project must run independently.

## Changes

- Never stage or commit files. The repository owner handles Git check-ins.
- Keep each example focused and follow its README.
- Ask before adding a shared framework, a cross-project dependency or a production dependency.
- Prefer a little duplication over hiding teaching code in shared helpers.
- Use OSS features where possible. Preserve essential EE features and document evaluation-license setup.
- Do not copy private project details, credentials or license keys into this repository.

## Documentation

- Use simple developer English and short explanations.
- Write READMEs and learning docs for the learner: explain what they can understand, run and observe. Keep authoring instructions and maintenance checklists in AGENTS.md or CONTRIBUTING.md.
- Mark planned examples clearly. Do not provide commands as working instructions until they work.
- Use diagrams when they help explain ownership, data flow or failure behavior. Keep editable sources with exported images.
- Keep Markdown paragraphs on natural lines without forced column wrapping.

## Validation

- Add meaningful tests for behavior changes and fixes.
- Test failure paths as well as successful results.
- Run the checks relevant to the files changed and report any checks that could not run.
- Review changes before finishing. Do not claim an example works until it has been run.
